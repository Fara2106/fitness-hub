## Stack constraints — DO NOT VIOLATE

Breaking these turns the app into a blank page.

- **React 18 via CDN + JSX precompilato al deploy (dal 2026-07-23).** Il browser carica UN solo bundle, `app.compiled.js`, generato da `dev/build.mjs` (`npm run build`): Babel standalone NON esiste più a runtime (via anche `unsafe-eval` dalla CSP). I sorgenti restano i `.jsx` del repo; ogni file è wrappato in una IIFE nel bundle → **ogni riferimento cross-file DEVE passare da `window.*`**: end each component file with `window.NomeComponente = NomeComponente;`. **Never** use ES `import`/`export`.
- **Dopo OGNI modifica a un `.jsx`: `npm run build`** (rigenera `app.compiled.js`, che è committato). `npm test` ha una Suite bundle che fallisce se il bundle è stale. Il deploy script esegue il build da solo.
- **Nuovo file `.jsx`** → aggiungilo a `BUNDLE_FILES` in `dev/build.mjs` nella posizione giusta (l'ordine conta: un globale va definito PRIMA del file che lo usa). `index.html` non elenca più i singoli file.
- **Persistence is `window.storage` only** (IndexedDB-backed, reads sync after init). **Never** use `localStorage`/`sessionStorage`.
- **No `<form>` tags** — wire `onClick`/`onChange` directly.
- After any edit, run `npm run build` + `npm test`. No browser test suite — verification is compile-check + unit tests + QA (Playwright locale e/o on-device).

## Sync v2 (PWA ⇄ fitness-hub-api) — dal 2026-11-03

Piano: `docs/superpowers/plans/2026-11-03-fase2-pwa-backend-v2.md`. Le schermate continuano a leggere/scrivere le chiavi locali di sempre (`checkIn_<data>`, `dietaCheck_<data>`, `schedaProg_<data>`, `weightLog`, `spesaChecked`, …): il **ponte** (`recordmap.jsx`) le traduce in record del backend a **gruppi** (`day:`/`variant:`/`cardio:`/`meals:`/`supps:`/`sets:`/`session:<data>`, `weights`, `measures`, `exNotes`, `prs`, `shopping`, `shoppingExtra`, `coach:<data>`, `settings`) e `syncv2.jsx` li sincronizza. Regole (non violarle):
- **Ogni scrittura utente va in storage NON silenziosa** (`storage.onChange` la vede → coda `v2outbox`, push dopo 1,5 s). Le scritture del ponte (pull, sweep 90 gg, restore) sono `{silent:true}`: non generano push.
- **Last-writer-wins per record**; `dayState` è **per campo** (`<data>:checkIn|hydration|notes|rest|dietVariant`, cardio `<data>:cardio:<id>`) così due device non si cancellano i campi del giorno. Spunta tolta = `done:false`/`checked:false`, non tombstone.
- **Primo sync di un device** (e dopo un cambio di `epoch` o un restore → `SyncV2.rebaseline()`): prima pull completo, poi push SOLO dei record che il server non ha → un device con dati vecchi non sovrascrive mai dati più nuovi. Le modifiche in coda vincono in locale sui record in arrivo.
- **Finestre locali:** `weightLog` 90, `bodyMeasures` 120, `activities` 50 voci e lo sweep a 90 gg tagliano solo in locale; la finestra si applica solo a lista piena → mai tombstone per ciò che esce dalla finestra.
- **Ruling 62: una serie mai toccata non produce record.** `schedaProg_.pesos` tiene solo i pesi toccati, digitati o registrati dalla spunta: `null` = mai toccata, `""` = svuotato a mano (a video resta vuoto, la spunta non registra peso). Le proposte (ultime sessioni, default) stanno a video e in `pesosRef`; `schedaShownPesos`/`schedaTickPesos` in `schedaState.jsx`. Il gruppo `sets:<d>` salta una serie non spuntata, senza peso, senza sostituzione e con record ignoto. Prima una Scheda aperta su un device non allineato scriveva `done:false` più recenti e cancellava per LWW le serie fatte altrove. Le pulizie di `sanitizeSchedaProg` sono silenziose.
- **Ruling 12 (esteso dal Ruling 64):** il gruppo `sets:<d>` non tombstona MAI un `setLog`, nemmeno di un esercizio del piano attivo: una spunta tolta è `done:false`, una voce sparita dal blocco è di solito una posizione cambiata. Piano cambiato con gli stessi id esercizio (riordino, inserimento, serie in meno, dall'app) → `SyncV2` rifà i blocchi `schedaProg_` dai `setLog` (`RecordMap.rebaseProg`), così il primo gesto non riscrive `done:false` le serie fatte. Piano nuovo con id nuovi: blocco invariato, decide `sanitizeSchedaProg` per nome e posizione, e le serie fatte restano nello storico.
- **Piani:** record `workoutPlan`/`dietPlan` (attivo = `status:"active"`, `validFrom` più recente), copia locale in `plan_workout`/`plan_diet`; le schermate ricevono le forme del parser via `PlanConv.toLegacy*`. Senza piano locale: testo legacy `schedaData`/`dietaData`, poi fallback embedded. **Import `.txt` temporaneo** (Impostazioni → Piani): nuovo piano attivo `workout-YYYYMMDD-HHMM`, il precedente `archived`. Integratori SOLO se il piano li prevede (niente lista fissa).
- **Chiavi device-local** (mai sincronizzate né nel backup): `syncToken`, `accountEmail`, `v2deviceId`, `v2cursor`, `v2epoch`, `v2outbox`, `v2grp:*`, `r:*` (cache record), `plan_*`, `groqApiKey`, `errorLog`.
- **Collegare un device (Task 9C, dal codice del 2026-11-03): account email + password.** Impostazioni → **Account** (anche passo saltabile dell'onboarding, `window.AccountPanel`): non collegato → «Accedi»; collegato col vecchio token e account non ancora creato → «Crea il tuo account» (`POST /v1/auth/claim`, una volta sola, solo col token legacy acceso); con account → email, «Cambia password», «Esci» (i dati locali e la coda restano). `syncToken` = la **sessione** (Bearer), `accountEmail` = email dell'account; **la password non si salva mai** (né storage, né `errorLog`, né URL). Il campo token incollato e il link `#sync=<token>` NON esistono più (il link è ignorato). Stato in `window._syncState` + evento `"lfh-sync"` (`idle|syncing|ok|error|offline|unlinked|expired`), badge `SyncBadge`. Campi `type="email" autocomplete="username"` / `type="password" autocomplete="current-password|new-password"` di proposito (portachiavi iCloud).

## Cross-device sync legacy (via il foglio `Settings`) — DISMESSO il 2026-11-03, solo storico

- `_cloudSync(opts)` tenta prima **`getAll`** (peso+settings in UNA chiamata, metà latenza/quota); feature-detect: backend vecchio senza `getAll` → risposta senza `.settings` → flag `_getAllUnsupported` e fallback alle due chiamate `getPesoCorporeo` + `getSettings` (per-call timeouts). **Anti-clobber: if the settings pull fails, `cloudKeys=null` and nothing is pushed** (prevents re-pushing stale local data). Cloud-wins on conflicts (last-writer-wins; no field-level merge).
- `_cloudPushMissing` pushes (with retry) only keys present locally but absent in cloud, and only if the pull succeeded.
- **Push settings (`_saveSettingRetry`, dal 2026-11-03): serializzato + coalescente per chiave** (si manda solo l'ultimo valore: prima le POST parallele delle spunte Spesa arrivavano in ordine sparso) e **"pending" persistito** in storage `settingsPending` finché il cloud non conferma. Il pull (cloud-wins) **salta le chiavi pending o confermate mentre era in volo** (`_cloudSkip`) e ri-pusha le pending al primo pull riuscito (`_repushPending`). Bug che risolve (riprodotto in Playwright): un pull concorrente riportava indietro un import scheda/dieta o una spunta appena fatta.
- **Reconcile `.txt` del repo (`_reconcileRepoFiles`)**: al PRIMO avvio su un device (`<key>_src` assente — anche la PWA aggiunta alla Home, che ha storage separato da Safari) registra solo la versione del repo, NON la impone né la pusha (prima cancellava ovunque la scheda/dieta importata a mano). Il repo vince solo quando il `.txt` cambia davvero rispetto a `_src`. Fetch con timeout 6 s.
- **Unione per voce tra device (`_MERGE` in app.jsx)** per `spesaChecked2`/`spesaExtra`/`exNotes`: le voci cambiate in locale vanno in storage `settingsEdits` (`window._markEdits(key, prev, next)` — chiamarlo in OGNI punto che modifica queste chiavi); alla push si rilegge il cloud (`getSettings`) e si manda l'unione; al pull vista = cloud + edits (`_pullMerged`), e le edits si cancellano solo quando il cloud le contiene davvero (altrimenti ri-push → convergenza anche se due device scrivono nello stesso istante). Stessa voce su due device → vince l'ultima. Formato nel foglio invariato.
- **Avvio non bloccante**: con `onboardingDone` la UI parte subito dai dati locali e reconcile+sync girano in background (`applySynced`); prima lo spinner aspettava fino a ~15 s con rete scarsa.
- Periodic pull every 45s while visible + re-sync on `visibilitychange` foreground.
- Synced keys: `schedaData`/`dietaData`, `spesaChecked2`, `spesaFreq`, `spesaExtra` (JSON), `bodyWeight`, `weightGoal`, `exNotes` (JSON), `onboardingDone`. `groqApiKey` NON si sincronizza (device-local). (Mesociclo/`weekNum` and RPE were removed 2026-07-14.)
